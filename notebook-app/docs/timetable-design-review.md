# 時間割・持ち物：調査と検証（2026-11-17）

## 参照した公式製品情報

- コクヨ キャンパス スタディプランナー: https://www.kokuyo.com/stationery/series/campus/study-planner/
  - 日・週の計画/TODOと、実績の見える化。今回の1日入力と週一覧を使い分ける設計の根拠。
- Class Timetable: https://classtimetable.app/
  - シンプルな時間割表示、複数週、課題メモ。番号と科目名で素早く確認し、補足は分離する方針。
- MyStudyLife Features: https://mystudylife.com/tour/ 、FAQ: https://mystudylife.com/faq/
  - 週や日で変わる学校の予定への対応。今回の日付別保存と前日/先週同曜日/任意日のコピーに反映。

製品の説明を調査したもので、有料版の実機比較・ユーザビリティの対照実験ではない。市販品を超えるという優位性を検証したものではない。

## 採用した操作

1. 1..8時限。科目・持ち物・教室/ひとことを直接入力。科目候補＋自由入力。
2. 持ち物は改行/読点で区切り、Unicode正規化した同じ名前を重複集約。使用する時限を併記。
3. 共通の持ち物と提出・連絡メモ。授業外の準備も同じ画面へ。
4. 準備チェック、未準備だけ表示、一括チェック。持ち物追加時は既存チェックを名前で維持。
5. 先週同曜日・前日・任意日からコピー。上書き確認とコピー直後の取消、準備チェックはリセット。
6. 今日/明日へ直行。週の表から日付へ移動。スマホは日別カードと横スクロール週表。
7. 保存済み/未保存/保存中/失敗/他端末との競合を区別。上書き競合は保存を停止し入力を保持。
8. 画面移動・ログアウト・再読込の未保存保護。選択中のタブを再度押しても保護を解除しない。
9. 日/週の印刷。編集欄の全文を印刷専用テキストとして表示。

## 独立レビューで直した点

- 同じ画面・日付への移動で親の未保存ガードだけ解除される問題。
- 科目空欄で書いた持ち物が週表から見えなくなる問題。
- モバイルナビの5項目対応、読込中の表示、印刷の長文欠け。
- 持ち物追加で全チェックが失われる挙動を、名前で保持する方式に変更。
- 8時限の深い入力検証でSecurity Rulesの評価数上限を超える問題を、型/長さ検査を維持して最適化。

## 検証

- 時間割モデル23 assertions：日付、入力長、64個上限、重複集約、チェック保持、コピー先の日付/版/参照分離。
- Firestore Enterprise emulator108 assertions（既存機能含む）：本人の保存/取得/更新、他UID/匿名拒否、深い8時限検証、型/長さ/余分なキー/CAS/時刻の不正拒否。
- ブラウザの操作体験：科目/持ち物入力、同名統合、チェック保持、未保存移動取消、日付移動、コピー時リセット、日/週切替。
- 390px幅のiframeで実レスポンシブレイアウトを確認。操作体験はメモリ内のみで、本人の実データは使用していない。

## 仕様上の限界

- WebプッシュやOCR、自動的な学校別の授業時刻入力は今回の範囲に含めない。個人の授業を学校公式の時間割として表示しない。
- 保存は明示操作。準備チェックも保存ボタンでまとめて保存。
- Rulesのpacked検査は0..63と重複拒否。実際の持ち物数未満かはUIモデルが検証。自己データ整合性の制約であり他ユーザーへの権限には影響しない。
- 個人の全記録をリアルタイム購読。記録量が増えた場合は期間別購読/ページングの検討余地がある。
